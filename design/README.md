# آزمایشگاه طراحی مینی‌اپ

پوشهٔ بازبینی طراحی — **بخشی از محصول نیست** و در `update.sh` هم استفاده نمی‌شود.
تنها ابزارش این است که چند مسیر بصری را کنار هم نشان دهد تا یکی انتخاب شود.

## اجرا

```bash
node design/serve.mjs          # http://localhost:4180/
```

`design/serve.mjs` ریشهٔ سایت را `design/ui-samples.html` می‌گذارد و همان
`public/miniapp.html` واقعی را برای قاب‌های پیش‌نمایش سرو می‌کند. هر چهار نمونه
دادهٔ نمونهٔ خود مینیاپ را دارند (بدون تلگرام و بدون سرور).

## نمونه‌ها

| نمونه | فایل تم | ایده |
| --- | --- | --- |
| **A — آبی زنده** | `variants/a.css` (خالی) | همین نسخهٔ فعلی؛ تعادل گرادیان نرم و شیشهٔ ملایم |
| **B — مینیمال آرام** | `variants/b.css` | بدون درخشش/سایه/گرادیان؛ خط مویی + یک آبی |
| **C — شیشهٔ نور** | `variants/c.css` | کارت‌های شفاف با بلور و نور آبی پس‌زمینه |
| **D — نئون** | `variants/d.css` | زمینهٔ تیره، شبکهٔ محو، لبه و عددهای نئون |

## قاعده

همان قاعدهٔ نسخهٔ اصلی: **هیچ متنی نباید به خط دوم برود** و چیدمان در ۳۲۰–۱۹۲۰px
باید سالم بماند. `scripts/check-miniapp.mjs` این فایل‌ها را هم می‌سنجد و اگر جایی
`white-space: normal` یا `overflow-wrap: anywhere` اضافه شود، بیلد شکست می‌خورد.

## بعد از انتخاب

لایهٔ برنده به‌جای پوشهٔ `design/` داخل `public/miniapp.html` (بخش «تم» انتهای
`<style>`) ادغام می‌شود و نسخه یک پله بالا می‌رود.
